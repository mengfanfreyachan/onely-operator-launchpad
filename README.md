# Onely Operator Launchpad

**一个面向 Onely 招聘作业的增长方案与可运行原型：72 小时内招募 100 位具备美国社媒运营能力的运营者。**

本项目是独立招聘作业，非 Onely 官方产品。未招募或触达真实候选人；演示线索、历史事件与统计均为虚构。100 人是带前置条件的计划目标，不是已实现的成果。

## 运行

Node.js 20+，无 npm 依赖、无需账号、Token 或模型额度。

```bash
git clone https://github.com/mengfanfreyachan/onely-operator-launchpad.git
cd onely-operator-launchpad
npm start
# 打开 http://127.0.0.1:4173
```

```bash
npm test
```

也可用任意静态 HTTP 服务器运行。请通过 HTTP 访问，直接双击 HTML 会阻止 ES Module / JSON 加载。默认仅监听本机；用 `HOST=0.0.0.0 PORT=8080 npm start` 可在自己的受控环境监听其他地址。

公开演示使用 GitHub Pages，无服务端数据库。界面在浏览器运行；当前数据存入 `localStorage`，刷新保留。不同设备、浏览器和同源端口之间不共享数据。可导出完整 JSON 备份；当前备份文件供归档，尚未实现一键恢复。导入 JSON **线索数组** 与导入备份对象是不同操作。

## 如何体验完整流程

1. “线索工作台 → 导入线索 → 导入带重复的示例 CSV”：12 行得到 **6 新增、3 重复、2 无效、1 身份冲突**。再次导入得到 0 新增、9 重复、2 无效、1 冲突。
2. 查看 A / B / C 预筛选及分项理由。本地模型只提供经历文本信号，A 级不等于合格。
3. 打开一位待触达运营者，生成 A / B 文案，编辑后确认渠道可联系、人工审核，保存。批量起草不会批量批准。
4. “导出已审核文案”只导出允许联系、审核通过且仍待触达的人。复制 / 导出不发送消息。
5. 在人员详情依次记录“已触达 → 已回复 → 已申请”。不可跳阶段；人工记录代表操作员确认发生过该事件，不代表邮箱投递验证。
6. 在“已申请”阶段核验美国运营证据、英文、18+ 和工作条款，实操评分 ≥75，才能记录“审核通过”。6 个月运营经验也是门槛。
7. 接受入驻后记录培训通过、首任务通过和账号 ID，才能记录“已激活”。账号 ID 为手工记录，未向 Onely 验证。
8. 初次触达 24h 后出现跟进提醒。生成一次跟进、人工审核并确认发送后记录事件；已回复、已拒绝、退订者退出队列。
9. 已激活者可记录合格任务；D1 / D7 留存只统计相应完整观察窗口已结束的成员。预置成熟窗口均为虚构示例。
10. 在增长总览调低积极回复率到 20%，预测激活人数从 102 降到 51，直观看见目标对温热渠道的依赖。

## 产品需求

### 用户与任务

增长负责人需要知道来源是否有效、下一步该做什么、谁真正具备美国运营能力；招募人员需要减少重复建表、写文案和盯跟进；培训负责人需要管理 100 人的审核、课程与首任务。

北极星是 **100 个唯一、经过能力审核、接受工作条件、完成培训与首任务的运营人员**。进群、填写表单或提交申请均不算激活。情感陪伴范围来自作业题目；官网确认的是 AI 创作者业务平台与粉丝关系能力。

### P0 功能与验收

|需求|已实现行为|验收依据|
|---|---|---|
|线索导入|CSV / JSON 数组，最多 10 MB / 10,000 行；格式校验|12 行示例与解析测试|
|跨渠道去重|大小写规范化邮箱、去跟踪参数的主页；同名不合并|重复导入与跨键冲突测试|
|资料保护|重复条目不覆盖已有审核、退订与历史；身份冲突留待复核|保留状态测试|
|预筛选|100 分规则 + A/B/C；逐项原因可展开|分级与地域无关性测试|
|AI 辅助|本地朴素贝叶斯文本分类，显示经验信号词|真实代码推理，无远端 API|
|个性化文案|姓名、月份、平台、市场驱动的 A/B 模板与一次跟进|浏览器演示及文案测试|
|人工审核|编辑文案撤销审核；批量起草后逐条审核|界面流程验证|
|触达状态|顺序推进；审核、激活有强制门槛|状态机测试|
|停止联系|退订 / 未通过成为终止状态；不导出、不再跟进|抑制与历史漏斗测试|
|运营统计|历史事件按人去重、原始来源归因、成熟窗口留存|统计与边界测试|
|计划模拟|起始线索量与各级转化率可调，区别于实际统计|情景计算测试|
|轻量存储|浏览器持久化、JSON 归档、明确重置|浏览器刷新验证|

### AI 与自动化，分别做了什么

**已实现的 AI 是轻量文本分类，不是大模型。** `SignalModel` 用 `data/training.json` 的 24 条人工编写的虚构短文本训练多项式朴素贝叶斯模型，做拉普拉斯平滑，识别更接近运营经历 / 泛化简介的文本。其得分最多贡献 10/100 分；少于 3 个已知词时不贡献分数。它用于排序和展示线索词，不验证工作经历，不独立决定录用。词频、拼接关键词或否定表述会误导模型；输出未校准，不能解释为“具备能力的概率”。

**文案是模板个性化，不调用 LLM。** 它引用导入资料的字段，描述 Onely 与试点工作范围，不杜撰客户、收入或候选人成绩。代码、方案、界面与演示制作过程中使用 Codex；运行时 AI 与开发时 AI 在这里明确分开。

**已实现的自动化**是格式检查、去重、分级、批量草稿、状态门槛、退订抑制、跟进提醒与统计。它把人工时间集中到证据核验、沟通和实操反馈。发消息、收消息、审批和支付仍须人工或后续集成。

生产版可接入自有服务端 LLM：只传获得授权的最少字段，要求结构化输出及证据引用；服务端保管 Token、限额、缓存、审计、超时回退。生成结果依然要审核。此接口 **未实现、未调用**，没有声称已获得任何免费大模型额度。

### 分级标准

|信号|分值|资料类型|
|---|---:|---|
|US 经验自述 / 仅欧美经验|25 / 12|候选人自述；US 证据须后续核验|
|运营 ≥6 个月|15|自述|
|Instagram / TikTok|15|自述|
|可提供作品|15|自述|
|英文自评 0–5|0–10|自评；后续英文测评|
|DM / 社群经验|5|自述|
|每周可投入 ≥10h|5|可用性|
|本地 ML 经验信号|0–10|模型辅助|

A≥80、B≥60、C<60。国家、性别、姓名不计分；欧美经验可进入待测评池，但最终入驻必须证明美国社媒运营能力。没有美国客户经历的人，可以通过美国账号分析与文化语境任务提供替代证据；此核验仍由审核员确认。

### 数据字段与流转

`id / name / email / profile_url / source / country / timezone / bio / months / platforms / markets / english / hours / portfolio / community / age18 / permission` 为导入字段；审核、状态与事件是本地工作流字段。导入时不会接受外部写入的 `qualified / activated / us_verified` 等字段。`source` 为原始获取来源，后续重复导入不改写。

每个邮箱、主页标识对应一名候选人。同一行的两个身份键指向不同已存在人员时进入冲突报告；重复行直接跳过，**不会自动合并新增联系方式**。只有名字相同不会去重。归并不同邮箱且无共同主页的同一人，需要人工补充标识后处理，当前尚未实现模糊身份匹配。

统计用 `events` 历史中的唯一人员数；同人重复事件不增加漏斗人数。退订保留此前触达记录。留存只计算激活后 D1 的 `[24h,48h)`、D7 的 `[168h,192h)` 合格任务，窗口完整结束才进入分母。被淘汰或退订的人仍留在已经成熟的激活队列分母中，避免虚高留存。真实工作量与质量还需外部任务审核。

### 成本模型：估算，不是已测量结果

完整增长计划见 [GROWTH_PLAN.md](docs/GROWTH_PLAN.md)。原型示范的自动化覆盖主要是信息处理环节：

|流程|人工基线假设|自动化后假设|节省|
|---|---:|---:|---:|
|1,600 条资料录入、清洗、分级|每条 3 分钟 = 80h|10h 资料抽检 + 4h 异常处理|66h|
|900 条首触达文案|每条 2 分钟 = 30h|每条 30 秒审核 = 7.5h|22.5h|
|900 人状态与跟进 / 统计|每条 1 分钟 = 15h|5h 事件确认 / 异常处理|10h|
|252 人能力与实操审核|每人 10 分钟 = 42h|每人 10 分钟 = 42h|0h|

上述可比流程从 167h 降到 68.5h，约 **59%**；不包括双方联络、支付、实操反馈等其他时间，也不代表原型已经自动接入平台。真实导入、筛选和审核耗时应在 200 人试跑中用计时日志验证。若源数据尚未结构化，资料准备成本不能忽略。模型不能代替 42h 的能力审核。

### 已实现与待验证

**已实现并可体验：** 上述 P0 导入、去重、规则 / 本地 ML、草稿、导出、跟进提醒、入驻门槛、历史统计、留存计算、计划模拟和本地保存。

**尚未实现：** 自动抓取社媒线索；平台真实发送、投递与回复 webhook；报名落地页与自动申请回传；Onely 账号创建 / 验证；Discord / Telegram Bot；LLM 自由文案生成；多人协作、认证、云端数据库和发薪。公开版只用于合成数据演示，导出数据和 localStorage 均不提供生产级保密或权限控制。

**仍需验证：** 伙伴 / 社群能否提供 1,600 条线索、40% 积极回复和 60% 能力通过；100 人是否能在 72h 内完成准入；试点报酬、平台额度和支付可用性；轻量模型真实表现；人工节约、首任务质量、D1/D7 留存。官网展示相关功能，但不证明这些招聘渠道、转化或 API 能力。

## 工程结构

```text
index.html / style.css / app.js     界面、浏览器工作流
core.js                            导入、模型、评分、状态机、统计
server.mjs                         零依赖静态服务器
data/                              24 条训练样本、30 个演示人员、12 行导入例子
tests/core.test.mjs                 业务约束和统计测试
tools/                             夹具生成、浏览器验证与演示录制
docs/                              增长方案、来源、验证记录
demo/                              演示播放器与脚本
```

公共 Pages 发布仅包含本项目代码、虚构示例与演示。账号密钥未写入仓库。表格 CSV 导出针对公式前缀加单引号；所有用户文本在 HTML 渲染前转义。

## 制作方式与资源

使用 Codex 开发；通过 agent-reach 的 Jina Reader / Exa 检索读取资料。Jina 首次读取超时，随后读取站点直接 HTML 文本确认首页；来源证据记录在文档中。代码运行使用本地 JS 模型，视频使用系统语音合成和 Playwright 浏览器录制，无需大模型 Token；公开代码和视频使用 GitHub / Pages。真实招募平台的付费账户与支付费用列为执行预算，未购买、未用于此演示。
